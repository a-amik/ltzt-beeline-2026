# Маршрут дня — сервер

FastAPI и OR-Tools, Python 3.12, пакет `src/bee_routing`, зависимости через
`uv`. Контракт сервера и интерфейса — [`../CONTRACT.md`](../CONTRACT.md),
он же главный источник имён полей. Описание решения для читателя —
в [документации](https://nami.amik.am/app/s/6118d05a96d7cf23ee93528c44bf11aa).

## Команды

```sh
uv sync                                   # зависимости
uv run python main.py                     # API на http://127.0.0.1:8000
uv run pytest --ignore=tests/test_benchmark.py   # тесты
uv run pytest tests/test_benchmark.py     # сравнение с контролем, отдельно
uv run ruff check .                       # линтер

uv run python -m bee_routing.prepare      # CSV заказчика из data/raw → data/datasets
uv run python -m bee_routing.matrices     # матрицы OSRM → data/matrices
```

`prepare` и `matrices` нужны только при новых исходных файлах: собранное
лежит в репозитории. Подготовка идёт в сеть только за неизвестными адресами,
найденное хранится в `data/geocode.json`, `--offline` запрещает сеть вовсе.
Матрицы считает локальный OSRM (порты 5100—5102); не ответил за пять минут —
берётся запасная оценка по прямой, и сводка говорит об этом прямо.

## Где живут числа

Любое число, от которого зависит план, задаётся настройкой или допущением,
а не кодом: его можно показать, поправить и сверить с новым ответом
заказчика.

| Что | Где |
|---|---|
| Рычаги диспетчера и руководителя: бюджет поиска, запас, реакция на аварию, доли, горизонты | `settings.py`: `DEFAULT_OPTIONS` и поле в `SCHEMA` с подписью, границами и подсказкой; форма настроек строится из схемы сама |
| Тарифы и цены | `data/assumptions.json`, ключ `economy` |
| Допущения о данных: длительности, навыки, транспорт, оборудование, поправки дороги | `data/assumptions.json`, у каждого ключ `_…` с источником |

Тест нового правила крутит именно настройку и смотрит, что план изменился
(`tests/test_intraday_rules.py`, `test_every_number_is_a_setting`).

## Модули

| Модуль | О чём |
|---|---|
| `checks.py` | одна функция `check_visit` — все ограничения: навык, транспорт, окно, смена, дорога |
| `baseline.py` | базовый вариант п. 2.3 задания, без оптимизации |
| `solver.py`, `arcs.py`, `objective.py` | решатель OR-Tools, матрицы дуг, порядок целей |
| `portfolio.py`, `ready.py`, `lns.py` | четыре стратегии параллельно, готовые утренние планы, фоновая доводка |
| `insertion.py`, `repair.py`, `replan.py` | вставка заявки, локальный ремонт, пересчёт после события |
| `explain.py` | объяснения назначений и причины отказа |
| `metrics.py`, `economy.py`, `risk.py` | метрики, экономика дня, риск окна |
| `benchmark.py`, `control.py`, `generalize.py` | сравнение с контролем и базовым, проверка на синтетических днях |
| `simulate.py`, `wave.py`, `stock.py`, `standby.py` | имитация дня, волна заявок, запас оборудования, точка ожидания |
| `crew.py`, `crew_app.py`, `fraud.py`, `transit_trip.py` | приложение бригады, контроль отметок, поездка по расписанию |
| `travel.py`, `day_profile.py`, `matrices.py` | время в пути: OSRM, поправки, час и тип дня |
| `prepare.py`, `geocode.py`, `upload.py`, `loader.py` | сборка наборов, геокодер, свой файл, чтение собранного |
| `api.py`, `models.py`, `settings.py` | HTTP, модели контракта, настройки |

Ограничения записаны в одном месте — `checks.check_visit`. Её зовут базовый
вариант, объяснения, вставка и ручная замена; решатель держит те же правила
измерениями модели. Второй набор правил рядом с ней заводить нельзя:
причина отказа в карточке заявки разойдётся с тем, что на самом деле не дало
её назначить.
