# Маршрут дня

Планировщик выездных инженеров для Билайн Бизнес: распределяет заявки дня
между бригадами, строит каждой маршрут по дорогам, перестраивает план после
события и объясняет каждое назначение словами. Задача № 3 хакатона
«Лидеры цифровой трансформации» 2026, команда «Лидеры цифровой прокрастинации».

- **Прототип:** https://bee.amik.am — стенд, собранный из этого репозитория.
  Без входа он работает в гостевом режиме на обезличенном наборе; данные
  задания открываются после входа по паре логин/пароль команды.
- **Документация:** https://nami.amik.am/app/s/6118d05a96d7cf23ee93528c44bf11aa —
  полная версия по разделу 5 задания: схема, логика оптимизации, метрики,
  тестовый набор, ограничения, справочник возможностей.

## Запуск

Нужны macOS или Linux (на Windows — WSL), Python 3.12+ с
[uv](https://docs.astral.sh/uv/), Node.js 20.19+ или 22.12+, `make`.

```sh
git clone https://github.com/a-amik/ltzt-beeline-2026
cd ltzt-beeline-2026
make setup      # зависимости сервера и интерфейса
make dev-api    # API на http://localhost:8000
make dev-web    # в соседнем терминале: интерфейс на http://localhost:5173
```

Прототип поднимается в гостевом режиме, как стенд без входа: сверху плашка
«Гостевой режим: данные обезличены» и кнопка «Вход». Войти в локальной копии
нечем: пара логин/пароль — у команды, а данные задания лежат только на стенде
и в репозиторий не входят. Без плашки — `BEE_MODE=local make dev-api`.

Наборы трёх участков, геокоды и матрицы дорог лежат в репозитории: прототип
поднимается без OSRM и без подготовки данных. Сеть нужна для установки пакетов,
подложки карты и геокодирования адресов из своего файла.

**OSRM** нужен для своего файла с новыми адресами и для новой заявки днём;
без него время до новой точки считается по прямой с множителем 1,3. Сервер
ждёт профили `car`, `bicycle`, `foot` на портах 5100—5102
(`data/assumptions.json`, ключ `osrm`):

```sh
mkdir -p ~/osrm && cd ~/osrm
curl -LO https://download.geofabrik.de/russia/central-fed-district-latest.osm.pbf
osmium extract -b 36.6,54.6,38.6,56.2 central-fed-district-latest.osm.pbf -o moscow.osm.pbf
IMG=ghcr.io/project-osrm/osrm-backend
for P in car:5100 bicycle:5101 foot:5102; do
  N=${P%%:*}; PORT=${P##*:}; mkdir -p $N && cp moscow.osm.pbf $N/
  docker run --rm -v $PWD/$N:/data $IMG osrm-extract -p /opt/$N.lua /data/moscow.osm.pbf
  docker run --rm -v $PWD/$N:/data $IMG osrm-partition /data/moscow.osrm
  docker run --rm -v $PWD/$N:/data $IMG osrm-customize /data/moscow.osrm
  docker run -d --name osrm-$N --restart unless-stopped -p 127.0.0.1:$PORT:5000 \
    -v $PWD/$N:/data $IMG osrm-routed --algorithm mld /data/moscow.osrm
done
```

## Тесты и отчёты

```sh
make test       # тесты сервера — на обезличенном наборе из data/
make bench      # сравнение с контролем и базовым тестами, отдельно от общего прогона
make lint       # ruff
cd frontend && npm test                               # тесты интерфейса (Vitest)

cd backend
uv run python -m bee_routing.benchmark 8              # отчёт сравнения → data/benchmark/report.md
uv run python -m bee_routing.generalize --days 10     # 10 синтетических дней на участок → data/generalize/
uv run python -m bee_routing.generalize --extra       # дни заказчика 28—29.09 против базового → data/generalize/extra-days.md
uv run python -m bee_routing.simulate vostok --seed 1 --policy offer   # имитация дня с событиями
```

## Как устроено

| Часть | Что делает | Технологии | Где |
|---|---|---|---|
| Интерфейс | экран диспетчера — заявки, инженеры, нагрузка по окнам (`/deficit`), живой день (`/live`), имитация: гонка трёх планов (`/sim`), отчёты (`/reports/…`), настройки; приложение бригады (`#crew/<бригада>`), экран руководителя (`#manager`) | React 19, TypeScript, MapLibre GL, Gravity UI | `frontend/` |
| Алгоритм и API | план, пересчёт после события, объяснения, метрики, сравнение | Python 3.12, FastAPI, OR-Tools, numpy | `backend/` |
| Данные | три участка и общий набор «Вся Москва» (открывается по умолчанию: участки считаются порознь, въезд бригады в чужой участок — штраф 2 000 ₽), матрицы дорог, допущения модели | JSON, OSRM, Nominatim | `data/` |

Граница между интерфейсом и сервером — HTTP по контракту [CONTRACT.md](CONTRACT.md).

**Оптимизация.** Решатель OR-Tools для маршрутизации с временными окнами,
четыре стартовые стратегии параллельно, бюджет 4 секунды (настройка «Время
поиска»). Планы сравниваются по очереди: больше заявок вовремя, затем меньше
бригад, затем выше итог дня в рублях — в нём через стоимость дороги
учитывается пробег.

**Цены.** Клиенты заказчика — бизнес, и цена заявки — то, что компания
теряет, если визит сорвался: подключение 7 000 ₽, ремонт 3 500, дозаказ 2 000.
Цена аварии зависит от сегмента клиента — ключевой, крупный, средний, малый,
микро (KA, A, B, C, D): счёт в месяц × срок договора × маржа × риск ухода
плюс эскалация, от 2 800 ₽ до 1 490 000 ₽; у крупных сегментов есть срок SLA.
Дорога стоит минутами инженера и проездом, сверх нормы дня — бонус, переезд
между зонами участка и въезд в чужой участок — штраф. Все числа — в `data/assumptions.json` и в группах настроек
«Ценность и приоритет» и «Затраты»; порядок ступеней авария → подключение → ремонт держится
сам, его проверяет `economy.balance_issues`.

**Ограничения п. 2.2** — навык, окно, смена, транспорт и оборудование —
проверяет одна функция `checks.check_visit`. Её зовут базовый вариант,
объяснения, вставка и ручная замена, поэтому причина отказа в карточке заявки
совпадает с тем, что не дало её назначить.

**Метрики:** `metrics.engineers_used` — бригад задействовано,
`routes[].distance_km` — пробег каждой, `metrics.distance_km` — суммарный;
после события `diff` называет, что изменилось.

**Данные.** Исходные CSV заказчика в репозиторий не входят (п. 7.3.5
положения конкурса). Собранные из них наборы, геокоды и матрицы лежат
в `data/`, правила восстановления полей — в `data/assumptions.json`,
разбор — в [data/README.md](data/README.md) и в документации.

Схема, ограничения прототипа, идеи развития и справочник возможностей —
в [документации](https://nami.amik.am/app/s/6118d05a96d7cf23ee93528c44bf11aa).
